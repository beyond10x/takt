# Metrics fields

The figures takt is judged by are kept as a committed series in `docs/metrics/`, JSON Lines, one
object per line. The three record files are appended to and never rewritten; `journeys.jsonl` is
generated from them. Token and cost figures come only from raw usage. A figure the source does not
state is `null`, never 0.

| file | one line per |
|---|---|
| `scenario-runs.jsonl` | scenario or variety run of any arm |
| `improvement-turns.jsonl` | improvement turn: a finding checked before and after a fix |
| `waves.jsonl` | wave merged into `main` |
| `journeys.jsonl` | operation of a run, in one vocabulary (generated by `journey.py`) |

## `scenario-runs.jsonl`

| field | meaning |
|---|---|
| `id` | the run's name in its source |
| `date` | UTC end of the run |
| `scenario` | scenario number; `null` for a variety run |
| `repository`, `unit`, `seed` | the repository worked on; for a variety run, the merged commit whose work it redid; the commit the run started from |
| `arm` | `takt`, `claude-code`, `codex` (harnesses running free with the operator's full configuration) or `claude-code-isolated` (takt's harness isolation plus a shell) |
| `takt_revision` | takt's commit; `null` for the free arms and where it was not recorded |
| `model` | the model the harness reported |
| `wall_seconds` | wall time of the run, resumes included |
| `steps`, `invocations`, `resumes` | takt steps to the finish line; runs of the command, and how many were resumes |
| `model_calls`, `harness_turns` | harness processes started; Claude's `num_turns`, summed |
| `tokens` | `input`, `output`, `cache_read`, `cache_write` and their `sum` |
| `cost_usd` | the cost the harness reported, API list price, notional |
| `stop`, `exit_code` | how the run ended |
| `pr_url` | the pull request the run opened |
| `acceptance` | the held-out check: `pass`, `fail` or `null` |
| `invocation_stops`, `after_approval` | per invocation: stop, steps, tokens, exit code; invocations after the approval, not counted in the totals |
| `notes`, `source` | what a reader needs to read the record right; the files it was read from, `~` for the home directory |

## `improvement-turns.jsonl`

| field | meaning |
|---|---|
| `id`, `scenario` | the turn's name and the scenario it was checked on |
| `finding` | the story that names the defect |
| `predicate` | the command `scripts/check-finding` ran on the scenario |
| `before`, `after` | revision, `reproduced` or `not_reproduced`, exit code, date and source of each check |
| `merged`, `reached_main` | branch, commit and date the fix was merged at, and the merge into `main` that carried it |
| `scorecard_result`, `scorecard` | the comparison of the candidate with the baseline |
| `outcome` | Canon's outcome for the turn's case, such as `accepted` |
| `promoted_at` | the revision the fix was promoted at; `null` until one is promoted |
| `source`, `notes` | the run record and case the line was read from |

## `waves.jsonl`

One line per wave: its title and a short label from `docs/waves/wave-NN.md`, the stories it
delivered, the merge commit into `main` and that commit's time. `closing_store_commit` is the
planning-store commit that closed the wave, where one is named. `measured_at` is the first
measured revision that contains the wave, when the merge commit itself was not measured.

The full field list, with where each value is read from, is
[`docs/metrics/README.md`](https://github.com/beyond10x/takt/blob/main/docs/metrics/README.md).
