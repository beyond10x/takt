## What takt does today

`takt run --repo R` takes the next ready story from the repository's planning store (or `--intent`
opens a case without one), opens a case on its own branch `takt/<id>`, runs the validators
(`tests.run` from `--test-cmd`, `gate.run` over `.engineering/gates.yaml`, `pr.open` and `ci.read`
through the bot forge when the origin is on github.com), lets the harness (Claude Code) take one
judgement step at a time, commits accepted steps, and stops at `ApprovalRequired (repository.merge)`
with the pull request open. `takt approve <case> repository.merge --by <approver>` writes the grant
and an approval record on the story; the next `takt run` resumes the case and merges through the
bot route. Evidence comes from validators only; the case directory is the kernel's; a run holds
its case.

## How the waves were run

`aep:implementing` 0.23.1 in wave mode: one story per wave, one integration branch
`wave/<date>-w<n>` from main, one managed worktree per unit, the implementor then two adversary
passes at most with a correction round after each, the coordinator verifying the final tree
(every gate command, exit codes read directly) before the merge, the domain document
`ess/domains/takt.yaml` kept true to the code at every close (citations re-pointed by text, the
statements the unit made false rewritten), the story's Scope rewritten as the unit landed, a
`test_result` record, the move to implemented, a closing commit, the merge into main, the trees
archived. Every review record is in the store verbatim (`review-result:adversary-*`).

Rules that held: stories are created with the planning skill, never free form; the wave cap of the
last goal was five; nothing is pushed, tagged or released without the operator's word; the
operator is told on Slack when something starts and finishes; every number in a report carries
its source or says "I don't know".
