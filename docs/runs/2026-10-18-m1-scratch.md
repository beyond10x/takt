# M1 run, 2026-10-18: one step validated on a scratch crate

The first real run of `takt run` with Claude Code as the harness, on a scratch Rust crate with one
function (`add(a, b)` returning `a - b`) and one failing test (`two_plus_two_is_four`), outside
every repository.

| item | value |
|---|---|
| takt | 0.1.0, `crates/takt` and `crates/takt-cli` at the first commit |
| protocol | `software.change/1` from `b10x-canon-engineering` 0.9.0; inputs `risk=trivial change_kind=feature affects_security_boundary=false` |
| harness | Claude Code, `claude -p`, file tools only, on the user's claude.ai login |
| validator | `tests.run` = `cargo test --quiet`, exit status to `test_result` pass or fail |
| command | `takt run --repo . --intent "make the failing test pass" --iterations 8 --input risk=trivial` |
| result | `stopped: ApprovalRequired (repository.merge)`, 4 steps, 28 s, 195,239 tokens (input, output and cache reads summed) |

The run, verbatim without the frontier lines:

```text
step 1: tests.run {}
  effect: the test command exited 101: fail; tests::two_plus_two_is_four … FAILED
  evidence: test_result fail
step 2: implementation.edit (claude-code)

  effect: committed 1 path(s); implementation is now 8fb6777b
step 3: tests.run {}
  effect: the test command exited 0: pass
  evidence: test_result pass
step 4: repository.merge (claude-code)
  said: Tests pass and implementation is verified per takt claims; … merge approval is requested.
  effect: none; repository.merge needs an approval
```

Final decision (`decisions/0004.json`): `tests.pass` true, `implementation.verified` true,
`repository.merge` approval-required. Evidence records: 2, both with producer `takt.tests-run`;
none from the harness.

## What the two earlier runs of the day found

- Run 1: every input a protocol declares must be given; the kernel had taken the first declared
  value, which made `affects_security_boundary` true and kept `implementation.verified` unknown,
  so the merge gate never opened and the harness inspected for five steps. Now the kernel refuses a
  missing input and the command line supplies the software change's least demanding values, said
  on the run's first line.
- Run 2: the governed check refused a `repository.inspect` step that "changed one path": the path
  was `Cargo.lock`, written by the validator's `cargo test`, not by the harness. A step's change is
  now the difference to what was uncommitted before it, and a discard keeps the case directory.
- A run that saw an API key in the environment refused it as invalid; the harness child now runs
  without `ANTHROPIC_API_KEY` and without a parent session's variables.
