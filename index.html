takt

One open-source binary that drives a repository's work through engineering protocols. Point it at a repository: it takes an intent or the next ready story, opens a case on a protocol, and lets a harness such as Claude Code take one admissible step at a time.

Nothing counts until a validator has turned an observation into evidence. Canon decides which claims hold and whether an outcome was earned; the model never does.

Agents choose how to do the work. The protocol defines what must be true before the work counts.

How it works

  • Protocol. A Canon document declares the claims, the actions, the evidence that establishes each claim, and the actions that wait for a grant, for example software.change/1 or story.delivery/1.
  • Case. Each unit of work (an intent or a story from the planning store) opens a case on a protocol, held as files in the repository.
  • One step at a time. Canon evaluates the case and names the admissible actions; the harness performs one of them in a worktree and reports. What it says is a trace, not evidence.
  • Validators make evidence. A program turns an observation (a test run's exit status, a commit, a merged pull request) into an evidence record bound to the revision it observed.
  • Grant before merge. A merge through the repository's bot route happens only under a recorded grant (takt approve).

Status

Use

takt run --repo <path> --intent "make the failing test pass" --iterations 1
takt run --repo <path> --hours 1
takt approve --repo <path> <case> repository.merge --by <who>
takt scenario run --repo <path> <id> --hours 1
takt protocols

Build with cargo install --locked --path crates/takt-cli. The README lists the requirements, defaults and exit codes.
