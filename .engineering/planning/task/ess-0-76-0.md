## What

ESS 0.76.0 is released. takt pins ESS only as a command-line tool, so the move is four files:
`ess/ess-inputs.yaml` requires ess 0.76, and `check.yml`, `darwin.yml` and the `Dockerfile` set
`ESS_VERSION` 0.76.0 with the SHA256 of the linux x86_64 and macOS aarch64 archives from the
release's `SHA256SUMS`. It rides in wave 43 under the rule that every repository uses the newest
ESS release.

## Library changes, not used by takt

`ess-composition`'s `TypeBinding::declared` returns `Option<&DeclaredTypeRef>`, and
`ess-domain`'s `Case` and `FieldCase` gain presence fields. takt depends on no ESS crate
(`Cargo.lock` names none), so neither change reaches it.

## Check

```expected_before
command: grep -qx 'requires: ess 0.76' ess/ess-inputs.yaml && grep -q 'ESS_VERSION: "0.76.0"' .github/workflows/check.yml && { echo "ess 0.76"; exit 0; } || { echo "ess older than 0.76"; exit 9; }
exit: 9
healthy_exit: 0
output: ess older than 0.76
```

## Acceptance

1. The predicate above exits 0.
2. `ess specify validate --path ess` with ess 0.76.0 says the specification is valid.
