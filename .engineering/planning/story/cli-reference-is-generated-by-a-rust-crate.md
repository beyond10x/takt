# Story: cli-reference-is-generated-by-a-rust-crate

## Outcome

The site's CLI reference and exit-code pages are written by a Rust crate of this workspace from
clap's command tree, committed, and drift-checked by `task check`; the site build only renders
them.

## Context

- Today `website/scripts/generate.mjs` builds the binary and writes both pages from `takt <command>
  --help` at site-build time (`generate.mjs:7-8`, `:158`, `:251-252`), so nothing in `task check`
  sees a help text change that the pages miss.
- The workspace rule for documentation sites: everything derivable (CLI reference, schemas,
  protocol pages, vocabularies) is generated by a Rust crate in the repository and drift-checked by
  `task check`; hand-written pages are concepts and guides only; only the site build is Node.

## Acceptance

Each item is a conformance scenario named in `ess/ess-inputs.yaml`, run by `task check`.

1. `docs/cli-reference-drift-checked`: a workspace crate writes `website/docs/reference/cli.md` and
   `website/docs/reference/exit-codes.md` from the clap command tree; `task check` fails when the
   committed pages differ from what it writes, naming the page.
2. `docs/generate-mjs-writes-no-cli-page`: `website/scripts/generate.mjs` writes neither page, and
   `task site-build` renders the committed ones unchanged.

## Scope

Inferred, not confirmed: a new crate under `crates/`, `crates/takt-cli/src/main.rs` (the command
tree exposed to it), `website/scripts/generate.mjs`, `Taskfile.yml`.
